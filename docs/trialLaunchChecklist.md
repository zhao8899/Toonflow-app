## 3. 交付规格与人工审片

- [ ] 接单前约定分段原片或整片、文件数与顺序、容器与编码、分辨率、画幅与容差、时长、帧率、音轨和内容限制。填写约定 ___，客户确认人 ___。
- [ ] 核对实际文件属性和哈希。已验证样片为 H.264、1256×720、24 fps、每段约 4.04 秒、无音轨。严格 16:9 的交付应按实测画幅验收，偏差由客户明确接受或暂缓交付。画幅溯源继续暂停。
- [ ] 审片人完整播放每段，检查主体一致性、明显形变、闪烁、黑帧、文字或商标、声音及模型输出异常。整片另按镜头顺序核对接点、节奏和音画，技术播放或单段审核记录不代替整片签审。
- [ ] 记录任务 ID、文件名和哈希、审核人、日期、结论（通过 / 返工 / 暂缓）及适用版本。交付仅采用已签审版本，并确认交付清单和接收人。返工涉及收费时重新核对剩余额度和授权。

## 5. 恢复研发的条件

只为可复现且影响试点的缺陷恢复对应开发。权限泄露、数据损坏或疑似重复扣费，先停止受影响操作并保留证据，再复现和定位。

| 问题类型 | 恢复研发的证据 |
| --- | --- |
| 核心流程阻断 | 已授权用户在约定场景反复无法提交、查询、恢复、播放下载或完成审片，已排查配置和上游状态 |
| 权限或数据问题 | 已确认项目或费用越权、成片或审片记录丢失、任务状态与实际文件不一致，可在隔离环境验证影响 |
| 重复生成或费用错误 | 原任务状态与提交记录可核对，任务 ID、账单及操作日志能指向产品侧重复提交或对账错误 |

每条问题记录版本、角色、项目、时间、任务 ID、预期与实际、影响范围和脱敏证据。单次未复现超时、上游故障、偏好和新功能建议先登记。每次试点复盘只汇总任务成功率及样本数、等待时长、人工返工、费用差异和实际阻断，据此决定维持试点、调整范围或恢复专项修复。
