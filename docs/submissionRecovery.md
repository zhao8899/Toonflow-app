# 成员视频提交恢复

范围：当前单进程、文件持久化的Toonflow实例；处理刷新、网络断开或响应丢失后的同一请求ID，不自动重发供应商生成，不自动退款。

## 恢复行为

浏览器仍只在当前标签页的sessionStorage保存账号对应的项目ID、目录及请求ID（version 1），不保存提示词、模型凭据或完整生成参数。原格式继续兼容；页面刷新后草稿内容可能需要重新填写。

- 查询到原任务：打开原任务所在项目的任务中心，不创建新任务，无论任务正在运行、已完成或中断；当前不是按任务ID自动定位详情。
- 查询404、超时、断线或权限错误：不能证明生成从未发生，保留原提醒，不自动清除，也不改用新请求ID重发。
- 用户选择“核对并恢复操作”：服务端校验当前账号、原项目及任务归属；若原任务存在，只返回它；若原任务未创建，先持久关闭该请求ID，再确认页面可解除提醒。
- 关闭标记保存失败、记录损坏、身份不符或响应无法确认：保持待确认状态。页面存储清除失败也保持提醒，可以再次核对同一个ID。
- 关闭成功后，原ID的迟到提交会被公共任务入口拒绝。只有用户明确再次提交时才使用新ID；页面不会自动生成。

刷新恢复入口可能没有父组件传来的项目对象，组件可使用已恢复的项目ID/目录作为上下文，并重新获取模型和额度；后端仍进行真实项目授权。切换账号、项目或卸载后的旧响应不能覆盖当前状态。

## 服务端边界

新增 `POST /api/ai/media/tasks/resolveSubmission`，请求 `{ directory, requestId }`，带原项目和期望账号标识，沿用认证、同源及项目成员校验。只核对本人请求，不开放取消其他成员任务或变更项目权限。

任务创建与关闭核对在单进程中使用同步存在判断和原子独占落盘，中间不插入异步等待：先创建则返回existing；先关闭则迟到create被拒绝。关闭标记单独保存为任务目录内的 `请求ID.submission.json`，不进入任务列表、额度或成本统计；包含身份与项目绑定，不包含提示词。

核对接口每账号每分钟最多30次，返回429及Retry-After；新标记写入前要求数据分区至少1GiB可用，避免新入口无保护写盘。它不是长期磁盘总量配额，标记需保留并纳入运维容量管理。已存在任务或关闭标记的核对不要求再次写入或重新调用模型。任务或关闭记录损坏时，不猜测“未提交”，按错误处理。

## 备份及回滚限制

关闭标记必须与任务和项目数据一起备份、恢复并保留，不自动到期或删除。删除关闭标记、恢复到标记产生之前的旧备份、降级至不识别标记的旧代码，都会失去对迟到请求的保护；不能将这种降级当作安全自动回滚。当前备份工具保持原规范挂载路径，跨路径迁移仍不在本轮范围。

本轮不迁移或删除真实数据，不部署生产。测试采用临时数据、执行回调或HTTP替身验证调用次数，没有真实供应商扣费验证。保证限定于请求ID、单写入进程及完整持久记录；不能承诺上游内部重复计费不存在，也不能阻止用户主动以新ID另发一个任务。当前标签页外的跨设备草稿恢复不属于本轮能力。
